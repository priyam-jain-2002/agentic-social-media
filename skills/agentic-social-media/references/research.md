# Research, firsthand insight and idea intake

## Intake
Record: exact observed event; what was expected; technical or commercial consequence; one primary reader; real proof; meaningful counterargument; confidentiality; potential publication window. Distinguish firsthand facts, reputable sources, inference and hypothesis. A valid analogy maps a real mechanism and states where it breaks, rather than decorating an otherwise generic opinion.

Internal pillars: BUILD, AI-SYSTEMS, PRODUCT, FOUNDER, MARKET-THESIS, OPEN-SOURCE, CROSS-DISCIPLINE and REFERENCE. Pick one primary and up to two secondary. These are NOT public hashtags.

## Weekly research loop
1. Fix dates and timezone, scan the preceding seven days, explicitly label older evergreen items.
2. Check original release notes, changelogs, engineering writing, standards, papers, source code and open issues across AI agents, inference, infrastructure, developer tooling, frontend, products and commercially important engineering problems.
3. Treat social discussions as evidence of reader questions and objections, not proof of technical assertions.
4. Deduplicate news syndication and earlier thesis posts; similar topic needs new experiment or genuinely different problem.
5. Convert each event into a reader problem and original testable claim; include link, publication/event date, source bias, counterargument and 20–90-minute proof experiment.
6. Apply S1–S8 signal gates: timely and verifiable; reader pain; original addition; technical/economic mechanism; relevant and novel; publicly safe; platform-fit; feasible proof.
7. If any material signal fails, HOLD or SKIP. Return 3–5 ranked candidates only if they qualify, and zero when none do.
8. Never claim having read connected private projects, run experiments or seen performance data unless actually obtained.

## Evidence hierarchy
Reproducible firsthand evidence > measured outcome and method > firsthand observation > original technical documentation > verified reporting > inference > speculation. Do not state a tentative proposal as law, a company claim as neutral test, or validation-set performance as an official result.

## Source examples
Use current public GitHub releases/issues, Hugging Face, PyTorch, vLLM, Vercel and Cloudflare engineering, Kubernetes, web.dev, Shopify/Wix developer docs and Google Search Central. Follow actual source URLs from discovery; don't invent release dates, statistics or versions.

## Privacy and storage
Ingest authorized project notes, but never echo confidential names, code, screenshots or metrics into public content without clearance. Return briefs and weekly radar results to chat or an approved separate private workspace; never into the public framework repository.
